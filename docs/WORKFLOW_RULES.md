# CodeChecker 開発・運用作業ルール (WORKFLOW RULES)

本ドキュメントは、CodeChecker プロジェクトにおける今後の開発作業・改修対応における運用ルールを定めたものです。
AI アシスタントおよび開発者は本ルールを厳格に遵守してください。

---

## 1. 調査と作業実施の分離（事前調査ファースト）

- **指示があるまでは調査のみを実施し、勝手なコード改修・作業実施は行わない。**
  - 不具合や課題が報告された場合、まずは原因調査、再現確認、影響範囲の特定、および改修方針の策定のみを行う。
  - 調査結果、根本原因、および具体的な改修計画をユーザーに提示し、ユーザーからの着手指示・承認を得てからコードの編集・作業実施に着手する。

---

## 2. Git コミットおよびリモートプッシュの運用ルール

- **AI アシスタントはローカルコミットのみを実施し、リモートへのプッシュ（`git push`）は行わない。**
  - タスク完了時やテスト通過時は、適切なコミットメッセージを作成して Git の**ローカルコミット（`git commit`）まで**を実施する。
  - GitHub リモートリポジトリ（`origin/main`）へのプッシュは、ユーザー自身が変更内容とコミットログを確認した上で手動で実施する。
