# CodeChecker 利用者マニュアル (User Guide)

CodeChecker は、ソースコードおよびWindows実行バイナリ（EXE/DLL）の脆弱性をハイブリッド方式（静的解析 ＋ AI解説・修正提案）で検出・可視化するデスクトップアプリケーションです。
完全ポータブル設計となっており、OSの環境（`AppData` やレジストリ、システムテンポラリ）を汚さず、アプリフォルダ内ですべて自己完結して動作します。また、すべてのWebリソースが内蔵されているため、**完全なオフライン環境（インターネット接続なし）**でも利用可能です。

---

## 1. 起動方法

### ① 通常起動（黒い画面を出さずに起動）
- **`run_silent.vbs`** をダブルクリックします。
- コマンドプロンプトの黒いウィンドウを立ち上げずに、デスクトップアプリの画面だけが直接起動します。

### ② ログ確認用起動
- **`run.bat`** をダブルクリックします。
- コマンドプロンプトが開き、起動ログやエラーメッセージを確認できます。

---

## 2. 脆弱性チェックの基本手順

1. **対象コード・ファイルの指定**:
   - フォルダ、`.zip` ファイル、または `.exe` / `.dll` ファイルをドロップゾーンにドラッグ＆ドロップ（または選択）します。
   - ソースコード（Python, JS/TS, Java, Go, C/C++, PHP 等）に加えて、**Windows実行バイナリ（EXE/DLL）の包括セキュリティ診断**にも対応しています。
2. **スキャン開始**:
   - 「チェック開始」ボタンを押下します。
   - スキャン中は、誤操作を防ぐためサマリーカードおよび一覧・詳細エリアにすりガラス調のぼかしオーバーレイが適用され、ロックされます。
3. **結果の確認 & フィルタ**:
   - 上部の **危険度 [高]・[中]・[低]** カードをクリックして絞り込みが可能です（各カードの左端には危険度カラーバーが表示され、選択中は枠線が内側にハイライトされます）。
4. **詳細 & AI解説の閲覧**:
   - 左側のリストから指摘をクリックすると、右ペインに該当コード（またはバイナリ情報）とAIによる解説・修正提案が表示されます。
   - **EXE/DLLバイナリ指摘のAI解説**:
     - ASLR/DEP/CFG等のエクスプロイト防御策の不備や、危険なAPI呼び出し（`strcpy`, `system` 等）、埋め込みシークレットに対し、AIがコンパイラオプション（Visual Studioの `/DYNAMICBASE`, `/NXCOMPAT`, `/guard:cf` 等）や安全な代替コード（`strcpy_s` 等）を具体的に提案します。
   - **エディタで開く / ファイルの場所を開く ボタン**:
     - **ソースコード指摘**: 「エディタで開く」ボタンが表示され、クリックするとVS Code（該当行ジャンプ）またはOS既定エディタで開きます。
     - **PEバイナリ（EXE/DLL）指摘**: ボタン表記が自動的に「**ファイルの場所を開く**」（フォルダアイコン）に切り替わります。クリックするとエディタでの文字化けやフリーズを防ぐため、OSエクスプローラーが起動し、該当ファイルが選択された状態でフォルダが開きます。
   - **リンクのスマート判別**:
     - 🌐 **Webリンク** (`http://`, `https://`): オレンジ色 `[↗]` で表示され、クリックすると**外部ブラウザ（EdgeやChrome等）**で自動的に開きます（アプリ画面が遷移することはありません）。
     - 📄 **ファイルリンク** (ソースファイル名): スカイブルーの破線下線 `[📄]` で表示され、クリックすると**VS Code等のエディタ**で該当ファイル・該当行を直接開きます。
   - **ZIPファイル検査時のファイル開きと注意通知**:
     - ZIPアーカイブを直接指定・スキャンした場合、アプリ内の一時展開フォルダ（`.temp/`）内のファイルが開かれます。この場合、エディタでファイルを編集・保存しても元のZIPアーカイブには自動反映されないため、画面右下に**警告トースト通知**が表示されます。
   - 右上の「コピー」ボタンで修正提案をクリップボードにコピーできます。
5. **レポートの保存**:
   - 右上の「レポート出力」ボタンをクリックし、Markdown（`.md`）または HTML（`.html`）形式で保存できます。レポートにはAIの解説・修正提案も網羅されます。

## 3. AIプロバイダの切り替えと設定

画面右側の**脆弱性詳細欄の上部ツールバー**から、AIプロバイダの切り替えやレポート出力を直接操作できます：

| プロバイダ | 特徴・用途 |
| :--- | :--- |
| **Ollama (ローカル)** | PC内のローカルLLM（`gemma4:12b-it-q4_K_M` 等）を使用（無料・完全オフライン、プロバイダ切替時の自動VRAM解放に対応） |
| **Codex CLI** | OpenAI の `codex` コマンドを使用（自動で読み取り専用サンドボックス `--sandbox read-only`・一時セッション `--ephemeral`・隔離作業ディレクトリで安全に実行） |
| **ChatGPT API (OpenAI)** | OpenAI公式 REST API を直接呼び出し（`gpt-4o-mini`, `gpt-4o`, `o3-mini` 等） |
| **Claude API (Anthropic)** | Anthropic公式 REST API を直接呼び出し（`claude-3-7-sonnet-20250219`, `claude-3-5-haiku-20241022` 等） |
| **Gemini API (Google)** | Google Gemini REST API を直接呼び出し（`gemini-3.8-flash`, `gemini-3.8-pro`, `gemini-2.5-flash` 等） |
| **AI無効 (高速)** | 外部通信やローカル推論を行わず、静的解析結果のみを瞬時に確認したい場合 |

### プロバイダ切り替えと再生成の仕様
- **脆弱性一覧での生成済み表示**:
  - AIによる解説・修正提案の生成が完了した脆弱性には、一覧リストの該当カード内に「**〇〇によって生成済み**」（例: `Ollamaによって生成済み`、`ChatGPT APIによって生成済み`）とバッジが表示されます。
  - 推論処理中や再生成中は非表示となり、詳細画面のバッジ描画と完全に同期して表示されます。
- **誤操作防止設計**: AIプロバイダを変更した時点では**自動再生成は行われません**。
  - 現在表示中の解説がどのプロバイダ・モデルで生成されたかは、見出し右隣のバッジで正確に確認できます（例: `ChatGPT API (gpt-4o-mini)`、`Claude API (claude-3-7-sonnet-20250219)`）。
  - 変更したプロバイダで解説を生成したい場合は、「**AI解説を再生成**」ボタンを明示的に押下します。
- **キャッシュの賢い活用**: 変更したプロバイダで同一セッション中に既に生成済みの場合は、APIやCLIを再実行せずキャッシュから即座に表示され、無駄なリソースやトークン消費を抑えます。なお、タイムアウトや通信エラーが発生した場合はキャッシュに保存されないため、いつでも安全に再試行できます。
- **プロバイダ状態インジケーター**: プロバイダ選択欄右側の丸いランプが、選択中のプロバイダの準備状態に応じて変化します（緑: 利用可能 / 黄: APIキー未設定または未検出 / 灰: AI無効）。

### 設定の変更と完全ポータブル永続化 (⚙ 歯車アイコン)
設定モーダルを開くと、各プロバイダの設定をきめ細かくカスタマイズできます：
1. **Codex CLI**: 実行コマンドの編集、指定モデルの手入力（datalistサジェスト対応）
2. **Ollama**: ホストURLの変更、インストール済みモデルの選択ドロップダウン
3. **ChatGPT API**: APIキーの入力、指定モデル（手入力 & 推奨リストサジェスト）
4. **Claude API**: APIキーの入力、指定モデル（手入力 & 推奨リストサジェスト）
5. **Gemini API**: APIキーの入力、指定モデル（手入力 & 推奨リストサジェスト）

- **テスト実行ボタン**: 各カード右上の「テスト実行」ボタンを押すことで、その場でCLIや各APIが正常に応答するか軽量な導通テストを行えます。
- **セキュリティ配慮**:
  - 設定済みのAPIキーは `••••••••` や `sk-...abcd` とマスキング表示され、画面共有や覗き見による漏洩を防ぎます。
  - キーを変更せずに「保存して閉じる」を押した場合でも、空文字で既存キーが消去されないよう安全に保護されます。
  - 「保存して閉じる」ボタンを押下すると、アプリフォルダ内の **`settings.json`** に自己完結保存されます（レジストリやOS領域を汚しません）。
